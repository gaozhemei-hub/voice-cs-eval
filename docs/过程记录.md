# 过程记录

项目于 2026 年 7—9 月在本地开展构思与产品初稿整理，10 月完成本轮实测与报告。以下记录聚焦 2026 年 10 月 11 日晚至 12 日上午的集中实施阶段，包括场景与方案细化、接口调试、正式实测和报告整理；这一阶段约一天，不代表整个项目的准备周期。

## 1. 选场景和方法论

- **场景选电商售后语音客服。** 它是实时语音模型最主要的 ToB 落地方向之一，客户对打断、判停、噪声和"不乱说"要求都高，而且对错可以客观核对。
- **原计划用一篇 C 端产品分析的经验帖做框架，最后只用了一半。** 它的"体验层""能力层"是为聊天助手设计的（上下文窗口、文档上传、UI 审美），对卖给企业的语音 API 不适用。保留了战略层和商业层，能力部分换成客服行业的评估方法。
- **指标体系参考一线外呼从业者的三层评估**（风险层一票否决 → 质量层 → 交互层），并借用 τ-Voice 基准"干净条件 vs 真实条件（噪声、旁人说话）"的思路设计噪声题。τ-Voice 本身只支持英文、接口不含国内厂商，没有直接运行。

## 2. 官网实地调研改变了测试路线

在三家官网和控制台实地查看后发现（截图见 `screenshots/`）：

| 发现 | 影响 |
| --- | --- |
| 阶跃体验中心能直接对话 3.0，但人设固定为"小跃" | 网页上无法设置客服人设 |
| 豆包官网公开 demo 跑的是 S2S 2.0，3.0 要在控制台开通 | 网页测到的不是最新版 |
| 千问AI平台和百炼都没有实时语音的网页体验 | 只能通过 API 测 |
| 千问最新版已是 3.1（文档 10-10 更新），不是资料里常说的 3.0 | 测试对象改为 3.1 |

**结论：网页只能测通用交互，客服核心题必须通过 API 统一人设才公平。** 于是放弃纯手工测试，改为自动化脚本。最初设计的手工测试方案保留在 `testset/测试题与打分表_初版手工方案.xlsx`。

## 3. 用合成语音代替真人

真人对着麦克风测三家，每家 26 题，既耗时又无法保证三家听到的话完全一样。改为：先用语音合成生成顾客音频，再由脚本按真实节奏推给三家。好处是可复现、三家输入完全一致；代价是合成语音太标准，识别类结果会偏乐观，这一点写进了报告的局限。

## 4. 踩过的坑

| 问题 | 原因 | 处理 |
| --- | --- | --- |
| 脚本连不上任何一家，报 SOCKS 代理错误 | 电脑开着系统代理，程序默认跟随代理 | 改为对三家直连。三家都是国内服务，走代理还会让延迟测量失真 |
| 豆包找 API Key 时进了"火山方舟" | 火山方舟是文本大模型平台，语音要在"豆包语音"控制台 | 换到豆包语音控制台新建 Key；两边的 Key 不通用 |
| 豆包控制台里看不到"3.0"字样 | 3.0 在控制台以"端到端实时语音"开通，命名不一致 | 开通后实测确认调用的是 3.0 全双工接口（model 1.2.6.1） |
| 豆包开通后仍返回 HTTP 403 | 鉴权请求头和文档示例不完全一致 | 脚本改为依次尝试几种鉴权方式，并打印服务端返回的错误说明 |
| 千问接口地址有多个版本 | 新版文档要求带业务空间 ID 的地址 | 脚本依次尝试业务空间地址和通用地址 |

正式测试前，脚本先在本地搭的模拟服务器上把完整流程跑通（含打断、附和、停顿、噪声），把格式问题挡在调用真实接口之前。

## 5. 数据处理与判分

- **延迟口径**：从"顾客说完最后一个字"到"模型发出第一段音频"。合成语音末尾带有静音，直接用"音频推送结束"计时会少算，因此扣除了每句音频末尾的静音时长（原始值和修正值都在 `results/latency.csv`）。
- **判停过早的识别**：同一句话里模型说了两次、或延迟为负数，说明模型在句中停顿处就开口了。千问 27 轮单句提问中有 9 轮出现这种情况。
- **判分**：逐题对照规则人工判分（`results/scoring.csv`）。有争议的一题是豆包 R1：它纠正了"30 天"的错误说法，但随后算错日期拒绝合规退货。最终按结果判为失败，因为顾客会直接投诉。
- **人工听评**：试听了三家"情绪与理解"对话的录音，豆包 Q11 文字正确但语气不够平和，判为部分通过。

## 6. 测试设计上的不足，下一轮要改

- **停顿判停题没有区分度**：顾客停顿 2 秒，三家都在停顿处开口。2 秒超过了三家的判停窗口，下一轮改为 0.5–1 秒。
- **打断后"多快停下"测不出来**：服务端提前把整段回复音频都发完了，API 层面看不到它何时停止播放。需要改用客户端实际播放时间来测。
- **判停参数不统一**：千问官方默认 800 毫秒，我设成 600 毫秒，可能放大了它的抢答问题。下一轮按默认值和语义判停模式各测一次。
- **每题只跑一次**：阶跃的延迟波动需要重复 5 次以上确认。
